# Phase 1 changes (created 2026-10-17)

Fixes to the data-collection pipeline, applied before any retraining. Every
number in the paper will be regenerated by the fixed evaluator; nothing here
is a benchmark result itself.

## Fixes

1. **Cached-scenario depopulation (blocking).**
   `Scenario::RemoveObject` erases objects from
   `objects_`/`vehicles_`/`pedestrians_`/`cyclists_`/`moving_objects_`, and
   `RestoreSnapshot` could only rewind surviving objects — so a cached
   `Simulation` lost every vehicle removed at goal/collision, permanently.
   `ObjectSnapshot` now keeps a `shared_ptr<Object>` plus its
   `moving_objects_` membership; `RestoreSnapshot` rebuilds every object
   container and the BVH (`nocturne/cpp/include/scenario.h`,
   `nocturne/cpp/src/scenario.cc`).
2. **Trivial goals (blocking).** `BaseEnv.reset` removed vehicles inside
   `goal_tolerance` (2.0 m) while `step` declares success inside
   `position_target_tolerance` (5.0 m), so episodes could start already
   solved. Reset-time removal now uses the same effective tolerance as the
   success check (`nocturne/envs/base_env.py`).
3. **Nondeterministic evaluation (blocking).** The evaluator drew a random
   scenario per episode and shuffled ego selection, and NoisyNet layers
   sampled noise during evaluation. Now:
   - `DDQNAgent.set_eval_mode()` disables noise sampling (noisy layers use
     mean weights) and epsilon-greedy; `load()` is guarded so it cannot flip
     noise back on.
   - `BaseEnv` gains deterministic eval mode (`cfg['deterministic_eval']`):
     the evaluator forces one scene per reset (`set_eval_scene`), ego choice
     is a pure function of the scene (largest remaining goal distance, ties
     by vehicle id), and a scene without a controllable vehicle is reported
     as invalid instead of silently substituted.
   - `evaluate.py` was rewritten: episodes are an explicit enumerated
     hash-split of `valid_files.json` (`scenario_utils.hash_split_files`,
     `'test'` half = even SHA-256 byte of `f"{split_seed}:{name}"`), and
     each run writes a JSON with full provenance (checkpoint sha256+metadata,
     scene-list sha256, env config, git HEAD + dirty flag, versions,
     seeds) plus per-episode metrics. `--log_steps` emits per-step traces.
   - `DDQNAgent.save` now persists `n_actions`; loading a checkpoint trained
     with a different action count raises instead of silently mismatching
     the action table.
4. **BC label offset (blocking).** `train_bc.py` paired the observation at
   `t` with the expert action from 10 timesteps earlier. Labels are now
   queried at `start_time + CONTEXT_STEPS + t`, matching the warmup offset
   (`CONTEXT_STEPS = 10`).
5. **Action set 15 -> 20 (roadmap decision, confirmed 2026-10-17).**
   `action_map.throttle_levels` is now `[-4.0, -1.0, 0.0, 2.0]`, adding a
   hard-braking level.

Supporting fixes found while verifying:

- `_autocast_context` returned a torch-1.12 autocast context with
  `enabled=False`, which still crashes on CPU fp16; it now returns
  `nullcontext()` when AMP is off.
- `test_smoke.py` trained a single step but asserted a host loss; the agent
  only syncs losses every `loss_sync_interval` steps. The test now runs a
  full sync interval.

## Phase 1b (implemented, found after this record was written)

Reviewing the arm matrix against the code exposed a paper/code contract
mismatch: `Scenario::OccupancyGrid` never receives the ray-cast visibility set,
so the occupancy grid contains occluded actors in *every* current mode. The
paper's method text requires visibility filtering of grid + TTZ, with only the
occlusion summary features toggling. Fixing this (visibility filter in the C++
grid, explicit `visibility_filter` / `occlusion_mask` / `history_frames` +
`history_stride` switches, observation metadata in checkpoints and the
evaluator) is a precondition for Phase 2 training.

Two further contract bugs were found while recovering the arm definitions:

- The reward reuses the observation TTZ, so enabling visibility filtering
  silently changes the reward source. The roadmap's `C_vis`/`D_vis` arms
  require an independent `reward.reward_ttz_source` switch
  (`privileged` vs `visible`).
- `train.py` hardcodes `grid_channels = 3`. The memory baseline (`C_hist`)
  needs grid-only history (3 frames, stride 5), so `grid_channels` must be
  `3 * history_frames` and the env must keep the grid deque.

Plan, frozen arm matrix, and implementation list:
`paper/workspace/phase2_arms_and_compute.md`.

Implementation and verification (2026-10-17):

- `Scenario::OccupancyGridVisible` filters actor stamps by the ray-cast id set;
  road edges are always stamped. Wired through `occupancy_grid_visible`.
- Config switches are orthogonal: `occupancy_grid.visibility_filter`,
  `use_occlusion`, `occlusion_mask`, `history_frames`, `history_stride`, and
  `reward.reward_ttz_source`. Observation TTZ and reward TTZ are computed
  separately; `info` logs privileged, observed, and reward TTZ.
- Grid-only history (`history_frames=3`, `history_stride=5`) yields the
  1809-D C_hist observation; `grid_channels` is `3 * history_frames`
  everywhere (train, BC, evaluator).
- `examples/drl_collision_avoidance/observation_config.py` is the single
  metadata contract. Every DDQN/BC checkpoint stores it; `evaluate.py` applies
  it and refuses checkpoints that lack it.
- `tests/test_observation_contract.py` (15 tests) covers dims, the A>=B grid
  subset, the C++ filter, reward decoupling, mask geometry, history padding,
  metadata round-trip/refusal, and agent save. Full suite: 58 passed (excluding
  the two pre-existing environment-limited modules below).
- All 8 arm configs smoke-tested at 300 steps; O and C_hist also at the
  production 4x12/48-env layout (1000 steps, 17 s each). O evaluated on 2
  test-half scenes through the real evaluator.

## Verification

- New regression tests in `tests/test_scenario_cache.py` (10 pass):
  snapshot restore reinserts removed objects; repeated cached resets keep a
  constant object pool; a removed vehicle returns on the next reset;
  deterministic eval picks the same ego for the same scene; no controlled
  vehicle starts inside the success radius.
- `examples/drl_collision_avoidance/test_smoke.py` passes (forward+train,
  MLP depth/optimizers, env interface).
- Evaluator determinism: two runs over the same scenes produce identical
  aggregates, episodes, and step traces; two different checkpoints see
  identical (scene, ego) pairs.
- Hash split on the full validation dir: 12,170 files -> 6,102 test /
  6,068 train, zero overlap, stable across recomputation.
- `test_dynamics.py`, `test_vec_env_restart.py` pass.

## Environment limitations (on this machine)

- No X11/Xvfb: `Scenario.getConeImage` aborts the process, so
  `tests/test_rl_env.py` cannot run here and SFML renders are unavailable
  for figures.
- `matplotlib` is not installed in the `nocturne-k80` env
  (`test_simulation_functions.py` cannot be collected).
- `gtest`/`gmock` are missing, so the C++ test executable link fails during
  `setup.py build_ext`. The extension itself builds; use
  `cmake --build . --target nocturne_cpp -j48` inside the build directory
  (or ignore the test-binary link error after `nocturne_cpp` reaches 100%).
